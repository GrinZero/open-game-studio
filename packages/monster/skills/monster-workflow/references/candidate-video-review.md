# 候选视频审阅规范 v1

契约标识：`monster-candidate-video-review-v1`。制作、补交或重建 Monster 候选动态审阅页时执行本规范；G1 的四候选是当前实现范围。

## 默认入口与显示

- 首要人工审阅入口是每个候选独立的小视频卡片，打开页面先看到视频。每张卡片明确标出稳定候选编号、自动检查状态，提供独立播放、暂停、进度拖动、正/侧/3⁄4 视角切换、全屏放大和单独打开视频。
- G1 完整保留 #0～#3，每套三个视角，共 12 段 `candidate_<id>_<view>.mp4`。宽屏两列、窄屏一列，主体占据各自画面；切换某张卡片视角时保留其时间与播放状态，不控制其他候选。
- 四宫格 `g1_candidates_sync_<view>.mp4` 放在默认折叠的补充比较区。技术说明、骨骼静态图和指标表可折叠查看，不能挤走首屏独立视频。
- 所有候选及真实 FAIL 效果均保留，状态可见。调整展示不改变模型、驱动、自动指标、检测阈值或用户决定；失败候选不能靠改布局成为通过。

## 同步来源与可追溯性

同批候选使用相同动作意图、实际时间线、帧率、相位、机位和灯光。独立视频从相应同步源的固定面板提取，仅裁切并编码，不选帧、不变速、不补帧、不为某候选另选有利动作。当前 G1 源为 1280×720，面板为 640×360，按左上 #0、右上 #1、左下 #2、右下 #3 映射；帧内保留候选编号、视角与帧号。

新 `g1_report.json` 保存 `presentation_contract`、12 段视频引用与 SHA-256、源同步视频 SHA-256、`crop_xywh`、实际编码 FPS 和逐视角帧数；HTML 同时带契约标识。审批和下游核验沿用现有材料哈希门禁，页面布局本身不构成用户审批。全 FAIL 时保留视频与指标，G1 保持 `not_ready` / `pending`。

## 入口与兼容边界

| 入口 | 必须执行的行为 |
| --- | --- |
| `monster_sop.py g1-pack`、`npm run monster:sop -- g1-pack`、直接 `sop_g1_pack.py` CLI / `build_g1_review_pack` | 共用同一构建器，默认产出完整 12 段独立视频、折叠同步比较、报告和材料引用 |
| `build_g1_review_html`，包括临时补审脚本 | 显式传入完整视频映射；旧调用未传时从真实同步源提取。缺候选、缺视角或缺文件则失败，不静默回退四宫格 |
| `encode_g1_candidate_videos` | 三个同步源必须齐全；按固定象限映射输出全部候选，不过滤 FAIL |
| `validate_g1_evidence`，由 `sop_gate.py` 审批与下游断言调用 | 新契约必须有完整 4×3 证据、引用一致且文件哈希匹配；保留历史未标记报告的读取与原审批兼容 |
| 云端 `rig_candidates` / 本地 `prepare_g1_candidates` Worker | 产出模型/元数据或同步原始帧，是 G1 包的上游，不能以 ZIP 或原始帧代替人工审阅页 |

历史已签名报告、旧 HTML 和部署快照保持原样，不批量覆写或伪造新契约。需要改善历史展示时，在新的 `reviews/G1/<review_id>/` 中从原视频生成展示修订，记录原报告路径及 SHA-256、源绑定版本、全部输出哈希和原决定；目录映射见 [角色工作目录规范](character-workspace.md)。仅展示修订不切换 `active.rig_id`，也不自动失效或重批历史有效决定。

本规范不要求为 G2 的 50 个静态随机姿势制造 50 段视频；G2 沿用姿势总览和逐图检查。G3 的原视频/重建同步对照与最终逐片动作验收保留各自契约，不扩展为四候选布局。

## 修改后的回归验收

运行 `packages/monster/.venv/bin/python -m unittest discover -s packages/monster/tests -p 'test_g1*.py' -v`。候选视频契约回归必须覆盖旧 HTML 调用自动升级、缺候选/视角/文件拒绝、12 段文件哈希及引用完整性、历史报告兼容、真实编码后的帧率/帧数/象限映射，以及全 FAIL 仍展示视频并保持门禁未通过。

浏览器核对四张编号卡片、各自三视角、独立播放/拖动、切换视角保持时间和播放状态、其他候选不受影响、放大及折叠补充区。代码更新按项目 AGENTS.md 构建并同步安装、缓存与实际 runtime；用户主窗口的刷新结果和新开的验证页面分别记录。
