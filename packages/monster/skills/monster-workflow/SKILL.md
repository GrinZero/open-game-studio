# Monster 工作流

以 [MonsterStudio 完整流程与用户审计规范](references/workflow-and-audit.md) 为制作依据。先读 [当前实现与操作入口](references/runtime.md)，确认正在使用的版本、能力与尚缺的保障；流程规范不代表 Worker 已实现相应功能。本技能不替代普通项目整理，也不因编写文档或检查代码而启动 GPU。

## 定位与恢复

确定游戏项目、`monster_id`、当前输入版本与用户此次范围。使用工作台时先读取对应项目与资源版本；没有工作台项目时沿用用户指定的文件夹，不自动登记其他项目。核对现有产物、阶段记录、用户反馈、云端 endpoint 和原提交记录，从第一个未满足前置条件的阶段继续。结果未知时查询原任务，不重新提交。

读 [审计记录与版本失效规则](references/reviews.md)。保留 G1/G2/G3 与最终批次验收的明确用户决定及所绑定的版本；现有同版本的有效授权继续使用。源文档、自动评分、Agent 建议和等待超时不能充当用户通过。通用角色技能允许的委托审核，不替代这条 Monster 流程的用户关卡。

## 按阶段执行

只读取和执行本次任务需要的 SOP 章节；不要把整条生产流程套到局部检查任务上。

1. **预检与 U1（SOP §2）**：保留原工程，从副本准备精简主体输入（`rig_input_variant`）。检查姿态朝向、实际几何原点归零（应用偏移变换防子分件塌缩）、装饰拓扑独立性（仅材质槽不同不算分离）、网格基础质量与正侧视遮挡；保留正常开口，不按材质机械切碎。视觉线索使用随部位运动的差异化图案，严禁采用左右纯改色。产出正/侧视实模检查图与输入清单，上传 Drive（U1）后让 Colab 从挂载的持久路径读取。不能用 Gradio 临时上传代替 U1。
2. **四候选、骨骼规范命名、装饰恢复与 G1（SOP §3）**：Colab 运行 SkinTokens 生成 4 套候选骨架，保存 `.blend` 与元数据至 Drive 并取回本地后，默认释放本任务独占实例。在本地将完整装饰恢复至 4 套候选模型（刚性挂件绑骨骼父级，柔性分件配蒙皮权重并保持独立分件，不焊接合并至主体），并**按 `<KIND>_<SIDE>_<GROUP>_<INDEX>` 规范重命名骨骼且同步 `vertex_groups` 与 `studio_rig_meta.json` 分类属性**（`KIND` 涵盖 `ROOT`/`RIGID`/`SPINE`/`HEAD`/`JAW`/`LIMB`/`WING`/`FLEX`/`TAIL`/`DIGIT`；历史匿名骨架如 `bone_0..N` 通过「命名规范＋自由度约束＋3D 拓扑几何」混合分类器自动补齐 `kind`/`subkind` 而不破坏已有训练权重索引）。按怪物形态（带翼类/人形类/四足或的多足兽/异形怪物）从参考库择一代表动作（建议 6～12 秒），在相同时间线、帧率、相位、相机和灯光下输出正/侧/3⁄4 视角同步对照视频，以及每套正/侧/背/3⁄4 的材质预览＋标准八面体（Octahedral）变形骨骼透显叠加图（共 16 张）与随动问题清单。准备完审阅包再请求用户指定唯一 `selected_candidate_id`。未获 G1 通过，不运行正式 50 姿势采样。
3. **50 个真实随机姿势与 G2（SOP §4）**：仅对 G1 选定的完整绑定模型运行正式合成采样器，**直接按当前锁定的目标视频生成分辨率渲染双视图原图**（默认最高稳定档位拼合 `1344×768`＝单视图 `672×768` 正视＋`672×768` 侧视；若开启 `ENABLE_2K_RESOLUTION=True` / `MONSTER_ENABLE_2K=1` 特性开关，则统一使用 2K 拼合 `2560×1440`＝单视图 `1280×1440`），生成 `pose_001`～`pose_050`（含正/侧正交双视图原图及 2D 标签叠加图、单屏 50 缩略图总览、关节随机范围与异常摘要）。采用充分且稍激进的联合随机，保留左右/前后肢体独立变化，仅拦截错误轴向、严重反折、几何撕裂爆炸或肢体脱离；固定 `seed` 并记录真实抽样与异常重抽对应关系，严禁反复换 seed 挑图或手工摆拍代替。等待用户认可随机策略，不能直接进入大规模合成或训练。
4. **U2、合成训练与 G3（SOP §5）**：确认当前模型与采样器具备有效 G1/G2 记录，模型有实质改动时先完成 U2（上传完整绑定 `.blend`/GLB、贴图与 `studio_rig_meta.json`）。**训练图与静止首帧基准图（`idle_split_1344x768.png` 或 2K 模式下的 `idle_split_2560x1440.png`）必须使用与目标视频生成完全一致的原生渲染分辨率**（`composite_width = panel_width * 2`、`composite_height = panel_height`；开启 2K 特性开关时，DINOv2 自动按 14px patch 对齐边缘填充至 `1288×1442` 并输出 `368×412` 热图，双视图极线同步阈值按面板高度同比例缩放至 `33.75 px`，严禁低清渲染后拉伸或跨分辨率混用）。**Blender 摄影棚渲染必须全链路开启硬件 GPU 加速**：Cycles 优先选择 `OPTIX` / `CUDA` / `METAL` 后端并将 `prefs.devices` 中的 CPU 设备设为 `device.use = False`（防 CPU 混合分块拖慢 GPU），**开启 `OPENIMAGEDENOISE` 时必须显式设置 `scene.cycles.denoising_use_gpu = True`**（Blender 默认该项为 `False`，若关闭会导致降噪回退至 CPU 并使 GPU 利用率跌至 ~6%），同时开启 `scene.render.use_persistent_data = True` 保持网格与 BVH 常驻显存、双正交相机锁定 `sensor_fit = "VERTICAL"`、三盏 Area Light 对准模型中心 `center`、表面可见性采样器缓存静态蒙皮权重与三角面归属。按约定合成训练集（基线默认 **5,000 姿态**，采用「40% 自然协同 `synergistic` + 30% 完全解耦 `decoupled` + 15% 反相/极值 `antiphase_extreme` + 15% 跨中线互遮挡 `workspace_cross_occlusion`」四模态分层解耦采样器，并在生成后执行 `audit_pose_dataset_coverage` 自动校验指间解耦有效秩、反相比例与分位数覆盖率，严禁五指固定比例同步卷曲或经验限幅过窄导致局部自由度冻结；含 v2.3 深度/表面可见性代理标签）并冻结 DINOv2 主干训练专属热图头与辅助头（基线 15 epochs；**DINOv2 注意力层必须绑定 PyTorch 原生 `F.scaled_dot_product_attention` 避免在无 `xformers` 时实例化 $N \times N$ 矩阵，开启 CUDA TF32 / `cudnn.benchmark`、多进程 `persistent_workers=True` + `pin_memory=True` + `non_blocking=True` 异步传输与无逐批同步累积**），备份旧权重后保存 `dinov2_head.pt`。使用独立于训练集、且具备相同双视图分辨率与相机标定的已有视频考试（原 96 帧合成序列仅作附加技术回归，不替代已有视频还原），执行抽帧、DINOv2 批量 `torch.inference_mode()` 推理、**三层通用＋Kind 专属运动学重建与烘焙**（仅 `<=3` 帧短遮挡 2D 插值、Savitzky-Golay 保峰平滑、多锚点 IRLS Kabsch 根姿态拟合、严格保持 `rest_offset` 的 FK 链式传递与正交双分支欧拉角限位，并按 `root`/`rigid`/`spine`/`head`/`limb`/`flex`/`digit` 分发专属求解器，其中 `forearm_hinge` 与 `hand_hub` 采用观测空间子骨锚点差分消除短骨端差与坐标混用偏差）、导出实际 GLB、重新导入 Blender 按原相机同分辨率（同为 GPU 光追＋GPU OIDN）重渲染。报告严格区分具 3D 真值（同时输出 `all_bones` 全骨、`primary_bones` 主干/四肢/飘带与 `by_kind` 分层指标）、仅 2D 标注、无标注原视频三类边界，不编造 MPJPE / SO(3) 数值。交付原视频与 GLB 重渲染并排同步对照视频、骨骼叠加、误差曲线与失败帧定位，由用户做出 G3 判定。
5. **生产动作与逐片交付（SOP §6）**：校验当前 checkpoint 具备有效 G3 记录后提交动作规格（如 `idle:loop walk:loop`，124 帧、24 FPS、8 步 Turbo，**MiniMax H3 模型权重默认采用 `H3_PROFILE="full"` BF16/FP16 满血版**）。**生成视频时必须与训练图及 `calibration` 标定分辨率严格一致**（默认单阶段 `1344×768`；开启 2K 特性开关时自动采用两阶段 2K 工作流：Stage 1 以原生 `1344×768` 采样 8 步保证双面板解剖与全局动作稳定，Stage 2 经 24 通道 3D 神经潜空间超分 `MinimaxH3LatentUpscaler3D` 升至 `2560×1440` 并执行 `MMH3SplitUpscale` 1344×768 滑窗重采样精修 4 步；禁止为提速或省显存降低最终视频分辨率或跨分辨率混用）。抽帧预测双视图骨骼端点并校验竖直同步，默认最多换 seed 重试 3 次；**重试耗尽仍未通过同步检查时直接终止并标记失败，禁止继续执行后续 IK 烘焙或输出不合格 GLB**。通过三层通用＋Kind 专属运动学重建生成三维轨迹并逐帧重置 Rest Pose 烘焙导出 `<action_name>_animated.glb`。回存 Drive（打包清单仅列本批产物，不混入历史遗留文件），本地重新导入 GLB 核验骨架、蒙皮、贴图与 `loop` 首尾接缝，逐片提交用户验收。原文件和历史结果不覆盖。

到达用户关卡时，先完成本次授权范围内可准备的全部审阅材料，再记录 `awaiting_*_review` 并给出材料、固定版本、具体待决定事项，以及所依据的本技能/SOP 条款。不要要求用户审批尚未制作的材料。只缺其中一个决定时，不重复询问已经明确且仍有效的决定。

## Colab 生命周期

执行云端工作或释放实例前读 SOP §7，并核查真实运行时配置；当前基线的自动释放行为与 SOP 冲突，不能仅靠文字要求它继续运行。

- 启动前盘点当前账号现有运行时和各任务 `--config` 登记，优先跨任务、跨会话复用；工作目录与日志隔离，GPU 任务排队执行。
- 四候选已回存 Drive、核验且取回本地后，默认释放本任务独占实例；随后保持本地恢复装饰和审阅，不空挂独占 GPU。
- 视频生成、用户查看、等待反馈及调参重生成全过程，持续保留并复用实例。单片完成、代码检查通过或等待回复期间均不关闭实例，也不安排额外定时关闭。
- 本批清单内全部视频的当前版本获用户明确满意后，完成收尾持久化并核验，再释放独占实例。
- 每次关闭前必做跨会话安全检查：核对目标实例 endpoint、账号运行时列表、所有本地 Codex 会话工作目录、后台进程与 GPU 队列。CLI 显示 `IDLE`、`[?]` 或瞬时 GPU 利用率为 0 均不等于无人占用；发现其他会话使用或排队依赖时严禁释放，仅保存结果并记录保留原因。释放后再次查询远端运行时列表核实已成功下线。

## 返修与结束

按 SOP §4.2 / §5.2 和审计记录依赖确定分级回退范围：仅采样策略问题改脚本重抽 50 个提交 G2（保留原 G1）；选定模型局部缺陷在本地修复后补交受影响的 G1 材料确认并重做 G2；自动骨架结构缺陷退回四候选生成 → 恢复装饰 → G1 → G2；输入模型基础缺陷退回阶段一预检与 U1 → 四候选 → G1 → G2；G3 失败按视频/标定/IK（修后重考 G3）、姿态泛化不足（退回 G2 重采样训练）或骨架缺陷（退回 G1）分级回退；**若升级或更改了目标视频最高分辨率档位，必须用相同最高分辨率重新渲染合成训练图并重训、重考 G3，禁止拿旧分辨率权重直接推理新分辨率视频**。

返回真实项目与资源版本、产物位置、锁定分辨率、已执行检查、当前关卡及 GPU 保留/释放状态。工作台导入采用不可变资源版本；导入不代表用户审计通过。未执行的 Blender 回读、用户验收、GPU 或引擎验证明确标为未验证。不要因新增技能而宣称后端门禁、Colab 迁移或生产流程已完成。
