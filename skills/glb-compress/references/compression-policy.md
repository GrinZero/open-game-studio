# 完整模型压缩规范 v1

适用时点：模型的几何、UV、材质和贴图已完整生成，准备交付或接入游戏。纹理、几何发生修改后重新评估。保留完整源文件；压缩结果是交付候选，不反向替换建模源、骨骼训练源或已固定审核的版本。

## 1. 项目规则

- **Godot 项目不开启 Draco**：所有候选使用 `geometry=off`，无论面数或预设。CLI 识别输入路径/当前目录的祖先 `project.godot` 和仓库的 `game/project.godot`；使用外部素材库时传 `--project`，只有引擎信息时传 `--engine godot`。显式 `geometry=on` 会报错，不输出伪兼容文件。已有 Draco 输入会解码后输出普通几何；不恢复之前丢失的精度。
- 其他引擎先使用相同的贴图对照流程。需要 Draco 时单独评估目标加载器支持和实际几何体积收益，不把 Draco 当作减面。
- 默认保留名称、切线、骨架、动画和形态键；不开容差焊接，不自动减面。KTX2 仅在目标加载/转码链已验证且需要 GPU 纹理压缩时另做候选，不能由 GLB 体积替代显存测量。

## 2. 先量化，再分流

`recommend.mjs` 输出三角形数（triangle count，三角化后的数量）、贴图载荷占比、源贴图尺寸、蒙皮/动画/形态键情况。区间是工作分流，不是统一的游戏预算：屏幕占比、UV 利用率、实例数量和最近观察距离都会改变结论。

| 三角形数 | 默认处理 | 几何处理 |
| --- | --- | --- |
| <10,000，低面 | 优先比较 WebP + 2K、WebP + 1K；保留几何 | 不因文件大而减面，先查贴图是否占绝大部分 |
| 10,000–99,999，中面 | 贴图优先；同时查看非贴图载荷 | 静态模型可另做保留 90% 的几何候选；不混入贴图对照，不默认采用 |
| ≥100,000，高面 | 判断体积主要来自贴图还是几何/动画 | 几何占主导时考虑独立减面或引擎 LOD；实际达成比例和轮廓决定是否采用 |

贴图 ≥70% 可视为“先做贴图”的强信号；<50% 时不能期待单靠贴图得到大幅缩减。中间区间两者都查。这些是排查顺序，**不是质量通过阈值**。即使面数很高，动画数据和重复顶点也可能是主要体积来源。

蒙皮/形态键资产默认只动贴图。若任务要求减面，独立检查关节弯曲、权重、表情和典型动作；静态画面的相似度不能证明动作没有损失。焊接也不是默认免费优化：UV、硬边和变形属性必须保留。

## 3. 选择 1K、2K 或更高分辨率

1. **保真优先从 2K 候选开始**。另生成 1K，固定相机、光照、曝光、动画采样时间、视口和过滤方式，对比原模型。
2. 游戏正常距离、最近允许距离都看；重点检查细木纹、钉子、文字/徽记、衣料缝线、法线凹凸、粗糙度高光、透明叶片边缘。选择在这些条件下没有明显损失的最小候选。
3. 1K 与 2K 都接近原版时选 1K；1K 模糊而 2K 接近时选 2K。2K 仍损失必要细节时试 4K/原尺寸，或保留原编码。不为达到压缩率强行采用可见劣化的版本。
4. 源贴图已经 ≤1K 时不放大；1K/2K 上限通常相同，只比较重编码与原图。源贴图 ≤2K 时 2K 候选是重编码，不应称为降分辨率。
5. 颜色图有损 WebP 会改变像素；法线、ORM 等数据图的误差还会改变光照。出现此类变化时保留原图或改为适合目标引擎的编码流程，不用更高分辨率名称掩盖编码误差。JPEG 不能丢弃原透明通道。

可用同镜头前景 SSIM、平均像素差帮助定位差异，但**不设跨资产统一 SSIM 自动通过线**。背景占比、光照饱和、极细透明边缘都可能掩盖问题。没有实际视觉对照时，报告“推荐试用 2K / 尚未选择”，不声称无视觉损失。

本地编码器当前 WebP 默认 quality=80。它是可复现的工具参数，不代表无损或网站相同画质；不同机器/编码器升级需重新评估。必要时保留源图，而非一律转换。

## 4. 验证与交付

- 临时产物统一到 `<项目允许的临时根>/glb-compression/<资产或批次>/`，包括 plan、候选 GLB、JSON 报告、截图及视觉结论。遵守项目自己的 scratch 约定；不把试做候选放进正式资产根或版本登记库。
- 单项对照先改贴图，几何另测。记录输入/输出字节、三角形数、各图尺寸、动画/蒙皮/形态键数量和扩展；记录目标渲染器、相机距离或屏幕占比、实际观察到的差别及采用原因。
- Godot 必须直接加载实际交付文件，不拿“解码后预览副本”当作 Draco 文件已兼容。Forward+ / Mobile 桌面预览分别记录；移动真机结果单列。
- 输出没有更小、节省不足以抵消可见损失，或仍未验证画面时，保留原文件是有效结果。不得为压缩而删除必要动画、名字或材质。
- 选择通过的固定候选再走项目原有交付/导入流程。普通模型压缩不新增一轮强制人工批准；已有角色审核关卡继续绑定原有版本，不能用一次贴图比较替代它们。

## 5. 默认加载的边界

此规则由 `glb-compress` 的发现描述及资源制作、角色制作/返修、资产交付 SKILL 的完成阶段入口加载。它是 Agent 制作流程的默认步骤，**不是目录监听器或服务端后台自动改写资产**。外部分发时复制完整技能目录，并在外部制作工作流的“几何 + UV + 材质 + 贴图完成”步骤加入：

> 默认加载 glb-compress 的压缩规范，识别目标项目，先生成候选与实际效果对照，再选择交付版本；Godot 禁用 Draco。
