# PBR 真实模型测试与精简规范

2026-10-30，使用获授权的 Starforger 模型做了 45 个候选，Godot 4.7.2 桌面 Forward+ / Mobile 各 408 张截图，共 816 张。这些样本展示了不同保真与体积取舍，不能推导出“只压颜色图”或“PBR 数据图无需处理”的统一规则。实际处理前需检查当前资产的载荷构成和编码；[港湾栏墙反例](harbor-pbr-study.md)显示，大材质 PNG 仅无损重编码也能明显缩小。

## 实际收益

以下为整份 GLB 的 MiB，所有候选关闭 Draco，保持顶点、三角形、蒙皮、动画和形态键数量。精确字节、贴图槽与逐通道误差见 [测试数据](pbr-study.json)。

| 模型 | 原版 | 全图 WebP 2K Q80 | 颜色 2K Q80 + 法线 2K 无损 + ORM 1K 无损 |
| --- | ---: | ---: | ---: |
| 铺路石 | 8.610 | 0.732 | 4.453 |
| 锻造棚 | 14.191 | 5.320 | 7.080 |
| 马 | 6.943 | 1.394 | 2.583 |
| 远景灌木 | 5.522 | 0.058 | 0.150 |
| 星盘 | 48.996 | 41.989 | 43.570 |
| 苔冠祭司 | 31.640 | 6.019 | 13.898 |

混合方案保留数据精度，体积比统一有损编码更大。它用于评估材质保真成本，不能当成额外省空间的默认优化。法线“无损”指缩放后的像素采用无损编码，降采样本身仍丢失细节。源图低于尺寸上限时不放大。

专项实验还包含只改颜色、只改法线（同尺寸无损/Q80）、只改 ORM（同尺寸无损/Q80）、颜色 1K + 法线 1K 无损 + ORM 512 无损，以及灌木 512 候选。未包含相应槽的模型不生成该单项实验。

## 观察到的差别

- **法线不宜统一套颜色图质量。** 铺路石单改法线时，Forward+ 四种光照近景的最差前景 SSIM：2K 无损 0.9993，2K Q80 0.9591；苔冠祭司为 1.0000 / 0.9489，Mobile 为约 1.0000 / 0.9429。祭司源法线已不超过 2K，无损重编码不改变解码像素；有损编码会改变树皮、枝条的受光细节。
- **法线编码误差因资产差异很大。** 对同尺寸无损参考和 Q80 结果，每隔 4 像素采样、解码并归一化向量，铺路石平均角误差 2.30°、95 分位 5.81°；祭司某张法线平均 4.83°、95 分位 24.88°。这些是编码误差，未把降采样误差算进去，也不作为统一自动验收线。
- **小 ORM 图可以保留。** 单改 ORM 为 1K 无损，在本次光照下对铺路石、锻造棚、马的渲染影响较小。祭司实际使用 AO，Q80 某张图 R 通道的像素绝对差 95 分位达 30/255；不能根据“灰度图看着简单”就统一有损编码。图像名称含 ORM 不等于 AO 槽实际启用，本次按材质绑定检查。
- **马的专项保真收益有限。** 正常全身和抽样 Idle 姿态下，统一 2K 与混合方案较接近；没有理由仅为默认流程增加一轮专项优化。最近用途仍以实际相机为准。
- **透明覆盖率相近不等于画质不变。** 灌木从 1K 降到 512，alpha≥0.5 的图像覆盖率约从 23.7091% 到 23.7076%，但近景叶片纹理和边缘仍变软。原尺寸重编码的 alpha 像素保持完全一致。颜色和材质变化仍需看渲染。
- **保留更高尺寸有价值。** 祭司混合方案的近景最差 SSIM 约 0.976，而更小混合方案降至约 0.818；树皮、叶片细节损失明显。不能把低成本配置强制用于所有角色。

## 按实际资产选择

先查看各图的编码、体积、尺寸和实际材质绑定。当前没有“只处理颜色图”的默认限制，也不要求对所有 PBR 图统一降分辨率或有损压缩。保留原图、无损重编码和有损/降采样都是可选结果，以实测节省和实际画面为依据。

对大 PNG 可以测试原尺寸无损重编码，逐像素验证后再声称无损；不要把调色板量化或缩图叫作无损。法线与 ORM 等数据图还需确认数据解释正确。有损/降采样需比较近景、不同光照下的凹凸、高光、颜色和透明边缘。Godot 的显存、运行性能由真实导入链另测。

当前 CLI 的 textures/resizeMax/mipmaps 是全图设置，不支持单张图的独立配置。只有这种统一处理适合当前资产时才执行；需要不同图分别处理时使用独立脚本或制作工具。以下实验方案是观测样本，不是默认预设或固定处理顺序。

## 方法与适用范围

直接读取真实原版与候选 GLB，使用同一资产的原版包围盒固定相机，640×640 输出，全景/近景各四个光源方向。Forward+、Mobile 均在桌面运行，保持材质参数、贴图槽和纹理过滤一致；双方同样生成 mipmap，法线 mipmap 使用法线归一化。马固定采样 Idle 的 37% 时刻，其余使用静止姿态。

渲染纹理使用解码后的 ImageTexture，以隔离源图编码和尺寸变化；本次没有测量 Godot 导入后的 GPU 压缩质量、显存或帧率。四个光源方向是离散采样，没有测连续移动的时域闪烁，也没有移动真机、HDR 自发光或完整动作循环验收。指标采用固定背景阈值前景掩膜，只作同资产对照。

测试未替换任何原模型或生产材质。全部候选、独立脚本、截图与原始报告集中在本工作区 `var/glb-compress/pbr-study-20261030/`，外部分发不包含用户模型或截图。

语义依据：[glTF 材质规范](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc)、[Godot 图像导入文档](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html)。整体交付规则仍见 [完整模型压缩规范](compression-policy.md)。
