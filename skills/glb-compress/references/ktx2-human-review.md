# 默认 KTX2 候选与人工对比

模型几何、UV、材质和贴图完成后，先检查实际载荷，**默认生成 KTX2（ETC1S / BasisLZ）候选，再让用户对比决定是否采用。** 默认保持源贴图尺寸（resizeMax=0），避免把编码变化与统一缩图混在一起。其他尺寸、编码、无损优化仍可按实际情况增加对照，不强制最终选 KTX2。Godot 继续关闭 Draco。

## 生成与真实预览

1. 保留原模型，把候选、配置、报告、截图与审核记录放在同一专用临时目录。`recommend.mjs` 默认给出 ktx2.json；`compress.mjs` / API 默认 textures=ktx2、resizeMax=0。
2. 默认编码需要 toktx。本地缺少编码器、贴图尺寸不满足 KHR_texture_basisu 的 4 倍数要求、颜色/数据共用图需要拆分或现有 KTX2 无法再转码时，明确报告阻碍；不静默换格式、缩图或把失败候选标为可用。
3. Godot 运行时加载先按 [KTX2 加载适配](godot-ktx2-loading.md)运行探针并使用随附脚本处理已确认的预线性化问题，再用目标渲染器直接加载实际 KTX2 GLB，确认扩展支持与显示效果。不能把解码副本的截图当作原候选已兼容。无法加载时，把失败告知用户，并可增加实际可加载的其他编码候选。
4. 原版/候选使用相同相机、灯光、曝光、视口、过滤与动画采样时间。至少包括正常使用距离与最近使用距离；有 PBR/透明图时，补充侧向或掠射光、高光/法线细节、透明边缘，动画资产补代表姿态。

## Human in the loop（必须等用户选择）

在聊天中展示标注清楚的原版/候选对照图，或提供可切换的实际模型预览；同时列出原/候选体积、减少比例、纹理尺寸/编码、所测渲染器、实际可见差异和加载情况。只给下载链接、体积数字或 SSIM 分数不能替代画面对比。

材料准备完成后，向用户提出一次具体选择，例如：

> 这组是同镜头原版与 KTX2 候选，体积分别为……。请选：采用此候选／保留原版／调整后再比较。

**停在此处，等待用户明确选择。** “默认开启 KTX2”的授权只允许自动生成候选，不等于用户已经接受这份结果。不得因体积更小、指标通过或 Agent 自己认为相似就自动采用。

用户确认前，报告与制作流程保持 `awaiting_user_comparison` / selected=null；不替换正式模型、不导入为正式版本、不标记验收通过。`compress.mjs` 仍可自动写出临时候选，这是审核材料；编码成功不是交付通过。

## 记录与后续修改

用户明确选择后，在本批次目录写 `user-review.json`，记录原版与候选路径、SHA-256（CLI 报告已提供）、截图/预览位置、渲染器、用户原话和时间、最终选择，再按原项目交付流程采用。用户选择原版或要求修改时照做；编码、尺寸、模型或材质变化后，重新生成对比并等待确认，不能沿用旧候选的认可。

编码器/API 返回的 review 字段只声明待审状态，不代替用户判断；本 SKILL 和资源/角色交付工作流负责执行等待关卡。已有 G1/G2/G3 审核继续绑定各自固定输入，压缩对比不替代那些审核。
